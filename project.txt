AI 공공시설 검색 에이전트 - 아키텍처와 파일 구성
==================================================

1. 전체 구조

프로젝트는 FastAPI 서버 하나에서 HTML 화면, 시설 검색 API, 에이전트 및 MCP 도구를 제공합니다.
화면은 Jinja2 서버 사이드 렌더링으로 만들고, 브라우저 JavaScript나 React는 사용하지 않습니다.
CSV 원본은 backend/data 폴더에 보관하며, ChromaDB 데이터베이스는 backend/chroma_db에 생성됩니다.

2. 폴더 및 파일 구성

3. 데이터 및 검색 처리

1) Pandas가 UTF-8 CSV를 읽고 필수 열, 공백, 결측치를 정리합니다.
2) 구조화 검색은 지역(전국/서울/경기/서울+경기)과 시설명·시설 유형을 데이터프레임에서 필터링합니다.
3) 임베딩 스크립트는 시설의 이름, 유형, 장소, 주소, 운영·이용 정보를 검색 문서로 합칩니다.
4) Sentence Transformers 다국어 임베딩으로 문서를 벡터화하고 ChromaDB 영속 컬렉션에 저장합니다.
5) 벡터 검색은 질문의 의미 유사도를 기준으로 결과를 찾으며 선택된 지역 조건도 적용합니다.
6) 상세 화면은 원본 CSV의 해당 시설 레코드를 표시합니다.

4. RAG 및 에이전트 동작

사용자가 질문을 보내면 에이전트는 설정된 OPENAI_API_KEY가 있을 때 모델의 도구 호출을 처리합니다.
에이전트가 사용할 수 있는 도구는 시설 검색(search_facilities)과 상세 조회(get_facility_details)뿐입니다.
도구 구현은 MCP 서버도 공유하므로 같은 검색 동작을 MCP 클라이언트에서도 사용할 수 있습니다.
모델 키가 설정되지 않은 경우 벡터 검색 결과를 근거로 간단한 RAG 응답을 만듭니다.
ChromaDB를 아직 만들지 않았다면 임베딩 스크립트를 먼저 실행하도록 안내합니다.

5. MCP 실행

프로젝트 루트에서 backend 폴더를 기준으로 `python -m app.mcp_server`를 실행하면
표준 입출력(stdio) MCP 서버가 시작됩니다. MCP 클라이언트 설정에는 backend 폴더와
해당 Python 실행 파일을 지정합니다.

6. 화면 구성 및 실행

- `/`: 지역과 검색 방식을 선택하는 검색 폼, 에이전트 질문 폼
- `/search`: 시설명·유형 구조화 검색 또는 벡터 유사도 검색 결과 목록
- `/facilities/{id}`: 운영 시간, 이용료, 주소, 연락처 등 상세 정보

실행 방법:
1) `cd backend`
2) `python -m pip install -r requirements.txt`
3) `python scripts/embed_data.py` (벡터 검색과 RAG를 위한 최초 1회 및 CSV 갱신 후 실행)
4) `uvicorn main:app --reload`
5) 브라우저에서 http://127.0.0.1:8000 접속

구조화 검색 및 상세 정보는 CSV만으로 동작합니다. 벡터 검색/RAG는 임베딩 완료 후 동작하며,
OPENAI_API_KEY는 모델 기반 도구 선택을 사용할 때만 필요합니다.
